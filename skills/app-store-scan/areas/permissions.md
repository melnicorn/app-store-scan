# permissions: purpose strings, privacy manifest, tracking, transport security

Guidelines 5.1.1(ii)-(iv), 5.1.2(i), 5.1.5, 2.5.14, 1.6 and upload validation. Each check: **ID** `[platform]` (guideline · usual severity when it fails).

**PERM-01** `[all]` (5.1.1 · blocker) Every protected API in use has its purpose string. The detector pairs API signals with `usage_descriptions`. Confirm each `fail` hint by opening the call site: an API that is really called without its `NS…UsageDescription` crashes the app on first use. Remember the less obvious ones: `NSLocalNetworkUsageDescription` plus `NSBonjourServices` for Bonjour browsing, UDP broadcast or any LAN connection on iOS; `NSFaceIDUsageDescription`; `NSPhotoLibraryAddUsageDescription` for save-only; `NSLocationAlwaysAndWhenInUseUsageDescription` when Always is requested; `NSUserTrackingUsageDescription` for ATT. Cross-platform projects: strings may live in `app.json`, `project.yml`, or a plugin config rather than a checked-in plist. Third-party SDKs can require strings too (the upload email ITMS-90683 names them).

**PERM-02** `[all]` (5.1.1(ii) · high) Purpose strings are specific. Each must say what is accessed and why, concretely, ideally with an example ("…to show nearby stores on the map"). Fail: empty, placeholder, a build variable, or only "App needs access to X". Warn: accurate but generic. Check every localization that overrides them (`InfoPlist.strings`, `.xcstrings`). Also compare the wording with what the code does: a string that understates the use is a fail.

**PERM-03** `[all]` (5.1.1(iii) · medium) No permission is requested that the app does not need. For each purpose string and entitlement with no matching use, either find the SDK that needs it or flag it. Flag full photo-library or contacts access where a picker (`PHPickerViewController`, `PhotosPicker`, `CNContactPickerViewController`, `ContactAccessButton`) would do; pickers need no permission and reviewers ask for them.

**PERM-04** `[ios]` (upload ITMS-91053 · blocker) Privacy manifest covers required-reason APIs. Applies to iOS, iPadOS, tvOS, watchOS and visionOS; it is not enforced for Mac App Store apps. If first-party code touches a category, the app's `PrivacyInfo.xcprivacy` must declare it with an approved reason:
- `UserDefaults` (incl. `@AppStorage`, AsyncStorage, shared_preferences): `CA92.1` own app data; `1C8F.1` app group; `C56D.1` SDK wrapper; `AC6B.1` MDM managed config.
- File timestamps (`creationDate`, `modificationDate`, `stat`, resource keys): `C617.1` files in the app container/app group; `3B52.1` files the user picked; `DDA9.1` shown to the user; `0A2A.1` SDK wrapper.
- System boot time (`systemUptime`, `mach_absolute_time`): `35F9.1` measure elapsed time in-app; `8FFB.1` event timestamps; `3D61.1` optional bug reports.
- Disk space (`volumeAvailableCapacity…`, `systemFreeSize`, `statfs`): `E174.1` check space before writing; `85F4.1` show to user; `7D9E.1` optional bug reports; `B728.1` health research apps.
- Active keyboards (`activeInputModes`): `3EC4.1` keyboard apps; `54BD.1` customize UI.
Confirm each detector hit is real first-party code that ships in the app (not a test, not a desktop helper, not an unrelated function named `stat`). Code compiled into the app from another language (Rust, C++, Kotlin) counts. Judge by calls your own source makes, in any language; internals of a language runtime or standard library that your code does not call need not be declared up front. Apple's upload email (ITMS-91053) is the final word on what the binary references: if one arrives, add what it names. Fail when a used category is undeclared or the manifest is missing; the fix should give the exact manifest entries. Also check the manifest file is in the app target's resources.

**PERM-05** `[all]` (upload ITMS-91061 · high) Third-party SDKs carry their own manifests. Use the `listed_sdks_present` hint: each Apple-listed SDK must ship a privacy manifest, and a signature when used as a binary. Fail when a listed SDK is pinned to a version from before early 2024 or its vendored copy has no manifest; otherwise pass, naming the SDKs.

**PERM-06** `[all]` (5.1.2(i) · blocker) Tracking only with App Tracking Transparency. Tracking means linking this app's user or device data with data from other companies for advertising, or sharing it with data brokers. If ad SDKs, the IDFA, or attribution/analytics SDKs configured for cross-app tracking are present: `ATTrackingManager.requestTrackingAuthorization` must be called before any tracking, the purpose string must exist, the app must work if the user declines, and no pre-prompt may pressure or incentivize consent. The manifest should set `NSPrivacyTracking` and `NSPrivacyTrackingDomains`. Fingerprinting to replace the IDFA is never allowed. No tracking SDKs: `na`.

**PERM-07** `[all]` (1.6 · medium) Transport security. `NSAllowsArbitraryLoads` true needs a justification in review notes: warn (medium), recommend domain exceptions. `NSAllowsLocalNetworking`, and exceptions scoped to named domains, are fine. Plain `http://` to internet hosts with no exception will simply fail at runtime: fail (high). Personal data or credentials sent over HTTP is a fail under 1.6 regardless.

**PERM-08** `[all]` (5.1.5 · high) Location is relevant and proportionate. Location must serve a feature the user can see. "Always" needs a background feature that justifies it; otherwise request When In Use. No emergency-services or vehicle-control use. The app must explain the purpose and still offer something (manual entry) when declined.

**PERM-09** `[all]` (2.5.14 · high) Recording is consented and visible. Camera, microphone, screen recording, session-replay SDKs and input logging need explicit consent and a clear visual or audible indicator while active. Session replay that captures screens without disclosure is a fail. Screen capture on macOS additionally needs user consent through the system prompt.

**PERM-10** `[all]` (5.1.1(iv), 5.1.2(i) · high) Permissions are never forced. Follow `permission_gate` and the code after each authorization callback. Fail when the app blocks use, withholds unrelated features or rewards behind enabling notifications, location, tracking or contacts; when it re-prompts in a loop; or when a custom pre-prompt has no way to decline. Denied permissions need a working fallback.

**PERM-11** `[all]` (1.6 · high) No shipped secrets. The `secrets` signal flags live keys or private keys in source. Confirm it is a real credential that would be compiled into or bundled with the app (not a test fixture or public identifier). Report the location only, never the value.
